# Native dedicated-database DBA preparation

[中文](NATIVE_DBA_PREPARATION.md) · [Read-only adoption](NATIVE_DEPLOYMENT.en.md) · [Native backup/restore](NATIVE_BACKUP_RESTORE.en.md)

This is a trusted DBA's one-time infrastructure operation, outside ordinary Agent authority. It is neither an environment scanner nor an arbitrary SQL interface. It accepts only a DBA-precreated, new empty dedicated PostgreSQL 17 database. Ordinary CONNECT and PUBLIC CREATE/TEMP must already be closed. The preprovisioned runtime login must have no superuser, BYPASS, database/role creation, replication, ownership or unsafe membership capability. The trusted DBA login must be the dedicated database owner and a superuser. The postgres/template databases, an existing global eb_app role and other application databases in the cluster refuse. The command never creates,clears,overwrites or deletes a database,or rewrites existing migrations.

```text
node scripts/enterprise-native.mjs prepare --config ABSOLUTE_NEW_PRIVATE_CONFIG_JSON --input ABSOLUTE_PRIVATE_REQUEST_JSON
```

The target follows native deployment directory rules and ends in `config.json`. `workDirectory` is a separate,new private directory;neither directory may contain the other. Paths must be absolute and canonical,without symlink files or indirect parents. The work directory retains audit metadata,commit intent,controller succession and failed evidence. It must remain private.

Initialization fields are `action:"initialize"`, `workDirectory`, `dbaDescriptorFile`, `dbaDescriptorSha256`, `runtimeDescriptorFile`, `runtimeDescriptorSha256`, `initialization`,and `initializationAcknowledged:true`, `dedicatedDatabaseAcknowledged:true`, `runtimeConnectGrantAcknowledged:true`. `initialization` supplies a required enterprise UUID,name,currency(CNY/USD/JPY/EUR;default CNY),timezone,HTTPS origin,port and the first identity administrator's username/password. Tool installation files are rejected. Passwords stay in private input files,never command arguments,preparation database audits or ordinary status output.

The strict DBA descriptor has `format:1`, `purpose:"enterprise-brain.native-prepare"`, `host`, `port`, `database`, `dbaRole`, `runtimeRole`, `enterpriseId`, `passwordFile`,and `tls:{mode:"verify-full",caFile:ABSOLUTE_CA_FILE}`. The runtime descriptor uses the established native runtime format with runtimeRole login and no purpose/dbaRole. Targets and enterprise identity must match. Exact descriptor SHA checks precede credentials;CA verification cannot be skipped and conflicting PG environment variables refuse. An actual runtime authentication probe must be rejected by the currently closed CONNECT ACL,so an incorrect password is discovered before commit.

All 28 unchanged migrations,the enterprise parent,one identity administrator,the fixed 14 host table grants,schema USAGE,SET-only eb_app membership,preparation audit and final CONNECT grant share one outer SQL transaction. The runtime login receives no BYPASS,DDL or blanket table grant. A private fsynced precommit intent binds cluster/database identity,code/migrations and complete data/catalogue/role-authority hashes. Failure to persist intent rolls back. An uncertain COMMIT response returns `native_prepare_completion_required`;it does not authorize assuming rollback and rerunning initialization.

After commit,a separate real verify-full runtime connection and native host factory verify qualification. No DBA object enters the host. Directory publication reuses native adopt,creating a fresh deployment identity,private tokens,an adoption receipt and parked/version0 traffic. Preparation never listens,starts the host,configures a model,installs MCP,runs background work or calls a model. Standalone `adopt` remains read-only access to an already prepared database.

After interruption,request `action:"inspect",workDirectory`. Inspection reads local files only and reports phase,controller liveness,`expectedJournalSha256` and `expectedOwnershipSha256`. Intent alone does not establish success. A `finish` request supplies the same directory,both exact hashes and `completionAcknowledged:true`. Succession is restricted to the same host and an exactly observed controller that has exited or explicitly released its claim. Live controllers,foreign/corrupt claims,stale observations and bounded succession capacity exhaustion refuse. No processes are killed,claims stolen by age or original claims deleted.

Finish requires unchanged original input,credentials and code,a precommit intent,the actual successful preparation audit and exact current database hashes. It verifies committed state and publishes/confirms configuration without replaying migrations,creating administrators or granting privileges. Changed data,ACLs,roles,target identity or audit refuse and remain untouched. Existing configuration must match a recorded adoption receipt,expected deployment fields and parked0 policy;another configuration is never overwritten. Failed staging remains private,new adoption attempts have distinct durable identities,and SQL commit plus filesystem publication is not a distributed transaction.

A failed task without intent or its matching successful audit cannot be guessed successful by finish. The DBA must review retained evidence and target state before a separate new request/directory. Automatic clearing or replay is unavailable. Private logs are not remote attestation against a host administrator/DBA. Native cross-version upgrades,clean hosts,Linux,live models and map publication clearance require separate acceptance;this contract does not claim those conditions are complete.

Existing publications/subscriptions,default grants,foreign-data wrappers,transforms,custom access methods or public collations/conversions/text-search objects are outside this new-empty-database contract. Initialization and finish reject them without automatic deletion or repair.
