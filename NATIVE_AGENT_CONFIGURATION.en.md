# Native Agent model and tool configuration

[中文](NATIVE_AGENT_CONFIGURATION.md) · [Native deployment](NATIVE_DEPLOYMENT.en.md) · [Backup and restore](NATIVE_BACKUP_RESTORE.en.md)

Native format2 deployments use `node scripts/enterprise-native.mjs` with `model-status`, `configure-model`, `tools-status` or `configure-tools`. Every command requires an absolute `--config`; changes also require an absolute private JSON `--input`. These commands operate on an explicitly prepared, adopted dedicated PostgreSQL database. They do not create databases, migrate, grant privileges, install services or start the host. Format1 commands retain their existing contract. Customers operate credentials, TLS proxies and hosts.

Model changes supply `principalId`, `expectedConfigurationSha256` and `action`. An `install` uses the existing `installation` contract: `expectedVersion`, `installationAcknowledged:true`, `descriptor` and `budget`. An `uninstall` supplies `expectedVersion` and `uninstallAcknowledged:true`. This is a trusted local operator instruction with access to private deployment files, not remote authentication by an account UUID. The current same-enterprise IT identity and authority version are checked again. Models use explicit local Responses/Chat Completions endpoints; customers may place a controlled compatible gateway locally for a remote provider. There is no discovery, weight download or cloud fallback. Installation never probes the endpoint or calls a model.

Stopped changes retain both a cooperative local claim and actual database session ownership. Another deployment owning the database, a local instance lock, unfinished backup or invalid claim refuses the change. Age never authorizes takeover; other processes are not terminated. Installation reuses durable quota identity and transactional CAS. Uninstall/reinstall preserves reserved calls and tokens. Restored unknown spend requires the existing reconciliation contract; ordinary installation cannot clear that fence. Safe summaries exclude credentials. Fixed error codes distinguish version conflicts, budgets below reserved spend and required restore reconciliation. Live status verifies native health, instance and configuration lock before sending a local-only control token.

Tool changes supply `expectedConfigurationSha256`, `expectedVersion`, `expectedPolicySha256`, `installationAcknowledged:true` and `toolInstallationFile`. The initial expected version is0 with a null policy hash. Installation uses an absolute private file; uninstall supplies null. Obtain current CAS values from `tools-status`. Existing contracts pin executable/adapter artifact hashes, argument subsets, roles, effects and MCP submit/lookup descriptors. Neither models nor business-source text select or install code. Status and installation inspect files without starting MCP processes or contacting sources.

The fixed `state/native-tools.json` sidecar binds deployment UUID, complete configuration hash, monotonic version and installation descriptor hash. The original `config.json` bytes remain unchanged, preserving exact configuration binding in completed backup journals. Absence selects the default read tool. Corrupt, foreign or changed policies/installations fail closed without deletion or silent fallback. Uninstall does not require the old executable to remain usable. Status excludes private paths, commands, arguments and environments.

The native host loads catalogues only inside actual database ownership and rechecks qualification after loading. Once a policy exists, catalogue versions bind its bytes. Reinstalling identical tools creates new versions, so restart or reinstall cannot implicitly renew old plans/approvals. Authorization and the post-metadata MCP handshake recheck policy, installation and current actor authority before new business dispatch. Accepted work or lost responses retain the original action UUID for receipt lookup rather than blind resubmission. Installation grants no business approval; delegation and supervision remain off by default.

New-database restore still revokes models, old approvals and external authority. It prepares a new parked0 deployment with empty state and does not inherit the source tool policy. This document does not certify production-model results, actual enterprise integration, Linux installation or native cross-version upgrades. Owned synthetic-company and local-protocol checks must be reported separately from actual business benefit.

Use [native allowance periods](NATIVE_BUDGET_PERIODS.en.md) for explicit post-restore new allowances. Do not use format1 commands or enable a model automatically.
