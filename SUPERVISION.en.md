# Background advancement of approved workflows

[中文](SUPERVISION.md) · [Graph contract](HOST.en.md) · [Receipt recovery](RECEIPTS.en.md) · [Enterprise host](HOST.en.md)

The independent enterprise host can advance an already compiled,independently business-approved acyclic graph after the browser closes. No delegation exists by default and no tool is called. The original owner must retain the original authority epoch and explicitly enable through a current business session/CSRF;IT cannot authorize business execution. This is not generic model planning,complete BPMN,all-vendor support or production-effect evidence. Default CLI tools remain process-summary reads;other tools require trusted programmatic installation.

GET/POST `/v1/graph/runs/{id}/supervision`. GET returns configuration version,enabled,state,code,interval,expiry,and cumulative attempts/failures. Strict enable JSON:enabled:true,expectedScheduleVersion(0 if absent),expectedRunVersion,supervisionAcknowledged:true;optional intervalSeconds5–60(default5),maxAttempts1–128(default64),ttlSeconds30–600(default120). Effective expiry is the minimum of requested/run/original approval deadlines. Enable requires ready/waiting_external,no live run lease,and no cancellation.200 confirms delegation,not business completion.

Strict stop JSON:enabled:false,expectedScheduleVersion. Current original owner or executive may stop;configuration conflicts return409. Stop does not cancel source transactions:dispatch already persisted before stop may finish and retain its receipt,but no new dispatch action is created after stop commits. Late results cannot re-enable work. Explicit reconfiguration confirms new supervision bounds without renewing original approval or resetting graph receipt budgets. Changed initiator authority cannot re-enable its old run.

Durable per-enterprise/run delegation pins plan hash,owner epoch,and installed-source/tool-catalog fingerprint. Every step reuses GraphService authority/approval/tool args/actionUUID/receipt contracts. Recheck delegation after authorization waits to prevent late dispatch after stop. Tool implementation changes must change tool versions;fingerprints cannot detect hidden changes in arbitrary trusted external implementations. Source is not hot-reloaded;old delegations suspend after a changed-code restart until fresh confirmation.

The host probes every second,at most one step per background round,with each task's own5–60second cadence.30second random leases/configuration versions supplement original15second graph fences. Consume one attempt before execution;crashes do not refund it.Max128attempts,at most3consecutive infrastructure failures;authority drift/expiry/manual states suspend and terminal runs disable. waiting_input after manual receipt recovery cannot resume automatically. Progress requires the service to remain running;this is not certified multi-node HA.

Background processing shares HTTP [park/drain](TRAFFIC.en.md). Unready/park/stop prevent new rounds;admitted work stays inFlight until actually finished. Stop pump before bounded drain/database close. Same-code restart may resume still-valid delegation. Encrypted enterprise restore suspends enabled delegations,increments configuration versions and clears leases;fresh confirmation is required even if the restored traffic policy is active.

Schema19 adds an enterprise-RLS delegation table without changing authoritative business ledgers. No dedicated business UI enable/stop controls yet;confirmation uses controlled APIs. Bare factories expose this API only with an explicitly trusted runtime fingerprint;their caller must install the pump/admission policy. The independent CLI installs them. Live models/Linux retain separate status;constructed protocol checks are not real business-efficiency claims.
