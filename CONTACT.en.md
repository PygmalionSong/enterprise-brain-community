# Discussion, collaboration and sensitive reports

[中文](CONTACT.md) · [日本語](CONTACT.ja.md) · [Home](README.md)

Use the official repository's [Discussions](https://github.com/PygmalionSong/enterprise-brain-community/discussions) for questions, process design and integration experience; use [Issues](https://github.com/PygmalionSong/enterprise-brain-community/issues) for reproducible defects and minimal installation reports. Maintainer: [PygmalionSong](https://github.com/PygmalionSong).

No project email is published yet, and obtaining source requires no email registration. A public discussion can describe a non-sensitive collaboration topic; the maintainer can clarify a suitable next contact route. Do not attach private commercial documents, contact details or customer information. GitHub has no general private-message inbox.

Never report sensitive vulnerabilities through public Issues, Discussions or PRs. Check whether the actual repository Security tab offers private “Report a vulnerability” reporting, and read the [security policy](SECURITY.en.md). If no private route is available, do not disclose sensitive details or secrets publicly. This document does not claim an unconfigured channel is active.

Review local reports before choosing to share them. Keep databases, keys, checkpoints and full logs private. No round-the-clock response or production SLA is promised.
