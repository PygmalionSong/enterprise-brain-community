# Repository discussion and contributions

[中文](REPOSITORY_GUIDE.md) · [Home](README.en.md) · [Contributing](CONTRIBUTING.en.md)

Use Issues for reproducible bugs, installation outcomes and redacted minimal reports; use Discussions for process design, integration experience and ideas. Readers need no write permission to ask questions or submit a PR from their own fork. Maintainers review official merges/releases; license reuse rights and repository write access are separate.

Documentation describes current distribution scope and capabilities, not internal commercial plans, personal information or unreleased iteration commitments. A feature suggestion does not create a delivery promise. Review source/test/doc changes through PRs; verify source-gate against the exact commit and actual repository settings rather than assuming enforcement.

Public feedback should contain versions, reproduction steps and reviewed minimal reports only. Never submit passwords, model keys, customer records, raw logs or databases. For sensitive vulnerabilities read the [security policy](SECURITY.en.md); do not open a public Issue.

Read the [support matrix](PREVIEW_SCOPE.en.md). This is a developer-source preview without the full operating cockpit or signed one-step installer, and it promises no universal vendor compatibility.
