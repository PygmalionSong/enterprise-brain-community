# Contributing

[中文](CONTRIBUTING.md)

Read the[repository guide](REPOSITORY_GUIDE.en.md)and[security policy](SECURITY.en.md).Use Bug for defects,Feature for proposals and Business discussion for process semantics/cases.Use constructed or explicitly public materials.

Submit a Pull Request from your fork;maintainer review controls the official branch.Describe the problem,resulting behavior,validation and limits with reproducible redacted steps.Do not upload credentials,enterprise data,logs,backups or private plans.

Keep changes focused.Reuse identity,authority,spend and action-receipt contracts.Accepting a source-system request is not business fulfillment.Update Chinese/English documentation and three-language UI resources with exact validation scope.

Prepare dependencies and run build,type checks/relevant tests as described in README.`node scripts/verify-repository.mjs` verifies source inventory only.File changes require an explicit inventory update;new hashes do not prove functionality.The original SDK source manifest remains a historical snapshot.Do not claim unverified hosts are supported.

Contributions use LICENSE and its applicable conditions.Disclose third-party code/data/license origins.Do not contribute materials you are not authorized to provide.
