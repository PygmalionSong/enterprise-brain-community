# Security reporting

[中文](SECURITY.md) · [Contact](CONTACT.en.md)

Never post exploit details, credentials, customer records, raw logs, databases or backups in public Issues, Discussions or PRs. Confirm that the actual repository Security tab provides an available private “Report a vulnerability” route before submitting sensitive details. If no private route is available, do not disclose secrets publicly.

Identify affected versions, preconditions, impact and a redacted reproduction. Do not request production access or unapproved actions. Ordinary defects can use minimal reproductions with constructed data.

Maintainers must enable and verify private reporting on the actual public repository. Planned settings are not active controls. README, HOST and native-operation documents define support limits. Licensing, hashes and passing tests are not production certification or an independent security audit. Operators retain responsibility for keys, network isolation, backups and audit. No undeclared-host or production SLA is promised.
